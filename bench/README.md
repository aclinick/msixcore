# MSIX Core (.NET) benchmarks & size tracking

This folder holds a **performance + binary-size benchmark harness** for the C#/.NET 10 port of
Microsoft's MSIX Core. Its purpose is to track the performance and footprint of this port over time
and to enable an eventual apples-to-apples comparison against the original C++ MSIX Core.

## Contents

| Path | What it is |
| --- | --- |
| `MsixCore.Benchmarks/` | [BenchmarkDotNet](https://benchmarkdotnet.org/) project measuring package open/parse, block-map verification, signature read, extraction, and loose-directory verification. |
| `Measure-Size.ps1` | Publishes the `msixmgr` CLI in several configurations and writes `size-report.md`. |
| `baseline-results.md` | A captured BenchmarkDotNet snapshot (regenerate as the code evolves). |
| `size-report.md` | The latest published-size report (generated by `Measure-Size.ps1`). |
| `Compare-Tools.ps1` | External-process head-to-head against Windows SDK MakeAppx. |
| `comparison.md` | Captured runtime and footprint comparison with interpretation and caveats. |
| `comparison-results.md` | Harness-generated median/min/max and memory tables. |

## Running the benchmarks

From the repository root:

```powershell
dotnet run -c Release --project bench\MsixCore.Benchmarks -- --filter *
```

Useful options (passed after `--`, forwarded to BenchmarkDotNet):

- `--filter *Verify*` — run only matching benchmarks.
- `--list flat` — list available benchmark ids.
- `--join` — combine results across types.

Results are written to `BenchmarkDotNet.Artifacts\results\` (git-ignored). Copy the
`*-report-github.md` into `baseline-results.md` when you want to record a new baseline.

The benchmarks synthesize their own packages in a `[GlobalSetup]` step (an OPC ZIP plus a matching
`AppxBlockMap.xml`, and a self-signed CMS `AppxSignature.p7x` for the signed cases), so no external
package fixtures are required. Extraction uses the real `MsixCore.Deployment.PackageExtractor.Extract`
API; extracted output is deleted in an `[IterationCleanup]` outside the measured region. The "large"
package is ~10 MB across 64 files so hashing/extraction throughput is meaningful. A short job
(`[SimpleJob(warmupCount: 3, iterationCount: 5)]`) keeps a full run to roughly a minute; raise the
counts for publication-grade numbers.

## Measuring published size

```powershell
pwsh bench\Measure-Size.ps1
```

This publishes `src\msixmgr` as:

1. **Framework-dependent** (host architecture; needs the .NET 10 runtime).
2. **Self-contained `win-x64`** and **trimmed `win-x64`**.
3. **Self-contained `win-arm64`** and **trimmed `win-arm64`**.

It reports total output size, file count, the CLI host size, and the largest `MsixCore*` /
`msixmgr*` assemblies, writing everything to `size-report.md`. Publish output goes to
`bench\publish\` (git-ignored).

The CLI uses source-generated JSON metadata, so trimmed publishing is now expected to
succeed. The report includes both `win-x64` and `win-arm64` self-contained and trimmed totals.

## Comparison against SDK tools

Run the like-for-like external-process comparison against Windows SDK MakeAppx:

```powershell
pwsh bench\Compare-Tools.ps1 -Iterations 7
```

The script deterministically creates 1 MiB, 10 MiB, and 64 MiB loose layouts, performs
one discarded warmup and repeated pack/unpack/validate runs, records wall time, peak
working set, and sampled private bytes, and verifies cross-tool package interoperability.
It defaults to native Arm64 MakeAppx for the primary native-vs-native comparison.
Override `-MakeAppxPath` with the SDK's `x64\makeappx.exe` for a separate,
clearly labeled emulation contrast. See
[`comparison.md`](comparison.md) for the captured results and interpretation.

## Interpreting results

- **Time** (`Mean`) — lower is better; `1 us` = 1 microsecond. Watch **block-map verification**
  throughput (SHA-256 over the payload) most closely — it is the fairest cross-language comparison
  point against the C++ core.
- **`Allocated`** — managed bytes per operation; the key "efficiency/size" axis on the runtime side.
- **Size totals** — compare the .NET framework-dependent column against a C++ build that relies on
  the OS CRT, and the self-contained column against a statically-linked C++ build.

## Comparison against the original C++ MSIX Core (future work)

The original C++ `msixmgr.exe` / `MsixCore` binaries are **not** in this repository, so no direct
comparison is produced yet. The intended methodology is documented at the bottom of `size-report.md`
and, for runtime, would re-run the same logical operations (open, verify, extract) against the C++
`msixmgr` on identical synthesized packages and identical hardware.
